# 系统架构设计

## 架构概览

POETIZE 博客系统采用前后端分离的微服务架构，基于容器化部署，支持高并发和可扩展性。

## 技术栈

| 组件                | 技术               | 版本             |
| ------------------- | ------------------ | ---------------- |
| **前端**      | Vue.js             | 2.x / 3.x        |
| **后端**      | Spring Boot + Java | 3.5.5 / 25       |
| **数据库**    | MariaDB + Redis    | 11.1+ / 7-alpine |
| **Web服务器** | Nginx (OpenResty)  | 1.29.2.5         |
| **部署**      | Docker & Compose   | Latest           |

## 核心模块

### 1. 前端层 (构建服务)

**poetize-web (Vue 3 前台+聊天室)**

- 博客主站前台 + 聊天室源代码
- 构建后输出到 Volume: `poetize_web_dist`
- 被 Nginx 挂载为 `/` 和 `/im` 静态资源目录
- 特性: 响应式设计、暗色模式、Live2D 看板娘、WebSocket 实时通信
- 构建完成后容器退出 (restart: "no")

**poetize-admin (Vue 2 后台管理)**

- 后台管理系统源代码
- 构建后输出到 Volume: `poetize_admin_dist`
- 被 Nginx 挂载为 `/admin` 静态资源
- 特性: 文章管理、用户管理、系统配置
- 构建完成后容器退出 (restart: "no")

### 2. 服务层

**Java 后端 (Spring Boot 3.5.11)**

- 端口: 8081
- 职责:

  - 用户认证授权 (JWT + HMAC-SHA256)
  - 文章管理 (CRUD)
  - 评论系统 (多级评论)
  - 社交功能 (点赞/收藏)
  - 文件上传
  - SEO 优化 (sitemap/robots.txt)
  - 邮件服务
  - AI 聊天配置


### 3. 数据层

> 📖 详细表结构请参考 [数据库设计文档](./数据库设计.md)

**MariaDB 11**

- 端口: 3306
- 多存储引擎优化:
  - InnoDB: 事务型表 (用户/文章/评论)
  - Aria: 读密集型表 (分类/标签/配置)
  - RocksDB: 写入优化表 (聊天记录)

**Redis 7**

- 端口: 6379
- 用途:
  - Session 缓存
  - API 响应缓存
  - 限流计数
  - WebSocket 在线状态

### 4. 基础设施

**Nginx (OpenResty 1.29.2.5)**

- 端口: 80/443
- 功能:
  - 反向代理
  - SSL 终端
  - 静态资源服务
  - 负载均衡

**预渲染服务 (Node.js)**

- 端口: 4000
- 用途: SEO 预渲染，提升搜索引擎收录

## 安全设计

### 认证授权

1. **Token 机制**

   - HMAC-SHA256 签名
   - 防伪造、防篡改、防重放攻击
2. **密码安全**

   - BCrypt 哈希 (替代 MD5)
   - 随机盐值
3. **OAuth 代理**

   - 支持海外平台代理
   - 解决国内访问问题

### 访问控制

- RBAC 角色权限模型
- 接口级权限验证
- 频率限制 (滑块验证码)

### Nginx 网关层防护

OpenResty（Nginx + LuaJIT）作为统一入口，在请求到达 Java 后端前完成多层安全过滤：

1. **IP 黑名单**：Lua 脚本在 access 阶段查询 Redis，命中黑名单的 IP 直接返回 403，fail-open 设计保证 Redis 不可用时正常放行
2. **空 User-Agent 拦截**：识别并拦截空 UA 或仅含 `-` 的请求（爬虫/扫描器常见特征），避免污染访问统计
3. **扫描器特征拦截**：直接断开对 `.php`、WordPress 路径、常见管理后台（phpmyadmin 等）及其他动态脚本后缀的探测请求
4. **敏感文件保护**：禁止访问隐藏文件、备份文件、配置文件（`.conf`、`.env` 等）
5. **IP 头伪造防护**：公网直连时拒绝客户端伪造的 `X-Real-IP` 等头部，只有可信内网/容器网络的反向代理传入的 IP 头才会被接受

## 快速开始

## 开发环境

```bash
# 启动依赖服务
docker compose up -d mysql redis

# 启动后端
cd poetize-server && mvn spring-boot:run

# 启动前端
cd poetize-web && npm install && npm run dev
cd poetize-admin && npm install && npm run dev
```

## 常见问题

### 部署失败

```bash
# 清理并重新部署
docker system prune -af
rm -rf awesome-poetize-open
bash <(curl -sL install.leapya.com)
```

### 内存不足

```bash
# 创建 swap 分区
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
```

### HTTPS 证书问题

```bash
# 重新申请
sudo docker exec poetize-nginx /enable-https.sh
```
