# 开发指南

本文档提供 POETIZE 博客系统的开发环境配置和各模块开发说明。

## 环境要求

| 环境 | 版本要求 | 用途 |
|-----|---------|------|
| Node.js | 14+ | 前端开发 |
| JDK | 25 LTS | Java后端（其他版本需改 pom.xml） |
| Maven | 3.9+ | Java项目构建 |
| MariaDB + Redis | 11 / 7 | 数据库 |
| Git | 最新版 | 版本控制 |

## 开发环境安装

### Node.js 安装

**Windows:**
- 下载安装 [Node.js LTS](https://nodejs.org/)，安装时勾选"Add to PATH"

**macOS:**
```bash
brew install node
```

**Linux (Debian/Ubuntu):**
```bash
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs
```

验证安装：`node -v && npm -v`

### JDK 25 LTS 安装

**Windows:**
- 下载安装 [Oracle JDK 25](https://www.oracle.com/java/technologies/downloads/) 或 [Eclipse Temurin](https://adoptium.net/)
- 安装后设置 `JAVA_HOME` 环境变量

**macOS:**
```bash
brew install openjdk@25
# 添加到 PATH
echo 'export PATH="/opt/homebrew/opt/openjdk@25/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc
```

**Linux:**
```bash
# 使用 SDKMAN（推荐）
curl -s "https://get.sdkman.io" | bash
source "$HOME/.sdkman/bin/sdkman-init.sh"
sdk install java 25-open
```

验证安装：`java -version`

### Maven 安装

**Windows:**
- 下载 [Maven](https://maven.apache.org/download.cgi)，解压后添加 `bin` 目录到 PATH

**macOS:**
```bash
brew install maven
```

**Linux:**
```bash
sudo apt install maven  # Debian/Ubuntu
# 或
sdk install maven       # 使用 SDKMAN
```

验证安装：`mvn -v`

### 数据库环境准备

开发前需要准备 MariaDB 和 Redis 服务，有以下三种方式（如需使用 MySQL 或了解多引擎优化，请参考 [数据库配置说明](#数据库配置说明)）：

#### 方式一：使用 Docker（推荐）

环境与生产一致，无需单独安装数据库。

**Windows 用户**：
* 需先下载并安装 [Docker Desktop for Windows](https://www.docker.com/products/docker-desktop/)。
* **安装与系统要求**：
  * 默认勾选并推荐使用 **WSL 2 后端**（保持默认的 **“Use WSL 2 instead of Hyper-V”**）。
  * **家庭版/家庭中文版用户说明**：WSL 2 后端只需要启用 Windows 自带的 **“虚拟机平台 (Virtual Machine Platform)”** 服务，**并不需要专业版/企业版独有的 Hyper-V 功能**。因此，Windows 家庭版完全可以完美运行 Docker Desktop。
  * **安装前置条件**：
    1. 确保在主板 BIOS/UEFI 中开启了 **硬件虚拟化 (Intel VT-x 或 AMD-V)**。
    2. 在管理员权限的 PowerShell 中运行 `wsl --install` 命令来一键安装 WSL 2 并开启所需的“虚拟机平台”功能，随后重启电脑即可。
* 安装完成后，后续的 Docker 相关命令均在 PowerShell 或 CMD 中运行，且**无需**添加 `sudo` 前缀。

> ⚠️ **运行前提示**：如果启动容器时报错 `ports are not available` 或 `port is already allocated`（端口冲突），说明你本地已运行了原生 MySQL/MariaDB（占用 3306）或 Redis（占用 6379）。此时你可选择停止本地服务，或**直接尝试 [方式二：使用已安装的本地数据库](#方式二使用已安装的本地数据库)**（因为你本地已有数据库环境，配置连接即可）。详细解决办法见下方 [💡 常见问题与端口/密码冲突解决](#-常见问题与端口密码冲突解决)。

```bash
# 启动数据库和 Redis（仅需首次执行）
# Windows（PowerShell）：
docker compose -f docker-compose.dev.yml up -d
# Linux/macOS：
sudo docker compose -f docker-compose.dev.yml up -d
```

#### 方式二：使用已安装的本地数据库

如果你的电脑已安装 MariaDB/MySQL 和 Redis，跳过 Docker 命令，配置本地连接：
1. **创建数据库**：使用终端命令行或图形化工具（如 Navicat、HeidiSQL、DBeaver）登录你的数据库，执行以下 SQL 创建名为 `poetize` 的数据库：
   ```sql
   CREATE DATABASE poetize DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
   ```
2. **导入初始化数据**：在项目根目录下执行以下命令（注意更换为你的实际用户名 `-u`，执行后输入密码）：
   ```bash
   mariadb -uroot -p poetize < poetize-server/sql/poetry_old.sql
   ```
   *(注：
   - **MariaDB 本地用户**：可直接执行上述 `mariadb` 命令；较老的本地安装可能也支持使用 `mysql` 别名。
   - **MySQL 本地用户**：请将命令开头的 `mariadb` 替换为 `mysql`。
   - **Docker 容器用户特别注意**：官方的 MariaDB Docker 镜像从 11.0 版本开始已完全移除了 `mysql` 命令行软链接。如果在容器内执行数据库操作，必须使用 `mariadb`（或 `mariadb-admin`、`mariadb-dump`），否则会报 `command not found`)*
3. **修改后端配置**：编辑 `poetize-server/poetry-web/src/main/resources/application.yml`，根据实际情况配置 `spring.datasource`：
   * **用户名/密码**：修改 `username` 和 `password` 为你的本地数据库凭据。
   * **MySQL 注意事项**：如果你使用的是 MySQL 而非 MariaDB，**必须**将 `driver-class-name` 修改为 `com.mysql.cj.jdbc.Driver`，并将 `url` 前缀从 `jdbc:mariadb://` 修改为 `jdbc:mysql://`（具体依赖修改和连接参数可参考下方 [从 MariaDB 切换到 MySQL 的详细步骤](#从mariadb切换到mysql的详细步骤)）。


#### 方式三：全新安装 MariaDB 和 Redis

**Windows**：
*   **MariaDB**：
    1. 下载安装 [MariaDB Server](https://mariadb.org/download/) MSI 安装包并运行。
    2. **密码设置**：在安装向导的 `Root password` 页面，输入新密码为 `123456`，并**勾选** `Use UTF8 as default server's character set`。
    3. **服务设置**：在后续页面中，确保勾选了 `Install as service`（默认服务名为 `MySQL` 或 `MariaDB`），默认端口为 `3306`。
    4. **创建并导入数据库**：
       * 打开 CMD 或 PowerShell，登录数据库：`mysql -u root -p`（输入密码 `123456`）
       * 创建数据库：`CREATE DATABASE poetize DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;`
       * 退出命令行：`exit;`
       * 在项目根目录下导入结构：`mysql -u root -p poetize < poetize-server/sql/poetry_old.sql`
*   **Redis**：
    1. 下载安装 [Memurai](https://www.memurai.com/get-memurai)（Windows 版 Redis 兼容替代）。
    2. 安装后自动作为 Windows 服务在后台运行（端口 `6379`）。默认不带密码，若需像项目默认配置一样设置密码为 `123456`，请打开 Memurai 安装目录下的 `memurai.conf`，找到 `# requirepass foobared`，修改为 `requirepass 123456`，然后重启 Memurai 服务。

**Linux**：
```bash
# Debian/Ubuntu 安装
sudo apt update
sudo apt install mariadb-server redis-server

# 1. 设置 MariaDB root 密码
sudo mariadb -e "ALTER USER 'root'@'localhost' IDENTIFIED BY '123456'; FLUSH PRIVILEGES;"

# 2. 创建 poetize 数据库
mariadb -uroot -p123456 -e "CREATE DATABASE poetize DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"

# 3. 导入数据表结构 (在项目根目录下执行)
mariadb -uroot -p123456 poetize < poetize-server/sql/poetry_old.sql

# 4. 设置 Redis 密码并重启
echo "requirepass 123456" | sudo tee -a /etc/redis/redis.conf
sudo systemctl restart redis

# CentOS/RHEL 安装与设置
sudo yum install -y mariadb-server redis
sudo systemctl start mariadb redis

# 1. 设置 MariaDB root 密码
sudo mysql -e "ALTER USER 'root'@'localhost' IDENTIFIED BY '123456'; FLUSH PRIVILEGES;"

# 2. 创建 poetize 数据库
mysql -uroot -p123456 -e "CREATE DATABASE poetize DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"

# 3. 导入数据表结构 (在项目根目录下执行)
mysql -uroot -p123456 poetize < poetize-server/sql/poetry_old.sql

# 4. 设置 Redis 密码并重启
echo "requirepass 123456" | sudo tee -a /etc/redis.conf
sudo systemctl restart redis
```

**macOS**：
```bash
# 安装并启动服务
brew install mariadb redis
brew services start mariadb redis

# 1. 设置 MariaDB root 密码
mariadb -u root -e "ALTER USER 'root'@'localhost' IDENTIFIED BY '123456'; FLUSH PRIVILEGES;"

# 2. 创建 poetize 数据库
mariadb -uroot -p123456 -e "CREATE DATABASE poetize DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"

# 3. 导入数据表结构 (在项目根目录下执行)
mariadb -uroot -p123456 poetize < poetize-server/sql/poetry_old.sql



```

> **注意**：开发环境统一使用密码 `123456`，生产环境请使用强密码。

安装完成后，按方式二配置数据库连接并导入数据。

#### 💡 常见问题与端口/密码冲突解决

##### 1. 端口冲突（Error: port is already allocated / Address already in use）

如果你在启动 Docker 容器（方式一）时遇到类似于 `ports are not available` 或 `address already in use` 的错误，说明你本地已经运行了 MySQL/MariaDB（占用 3306 端口）或 Redis（占用 6379 端口）服务。

**解决办法 A：停止本地运行的服务（推荐）**
* **Linux**:
  ```bash
  # 停止本地 MySQL/MariaDB
  sudo systemctl stop mariadb  # 或 mysql
  # 停止本地 Redis
  sudo systemctl stop redis-server  # 或 redis
  ```
* **macOS**:
  ```bash
  # 停止本地 MySQL/MariaDB
  brew services stop mariadb   # 或 mysql
  # 停止本地 Redis
  brew services stop redis
  ```
* **Windows**:
  1. 按下 `Win + R` 键，输入 `services.msc` 并回车。
  2. 在服务列表中找到 `MySQL`、`MariaDB` 或 `Redis` 服务。
  3. 右键点击对应的服务，选择“停止”。
  4. （或在管理员权限的 PowerShell/CMD 中运行：`net stop mysql` / `net stop mariadb` / `net stop redis`）

**解决办法 B：修改 Docker 映射端口**
如果你不想停止本地服务，可以修改 `docker-compose.dev.yml` 中的外部端口映射（冒号前的部分），例如：
* 将 MySQL 的 `"3306:3306"` 修改为 `"3307:3306"`
* 将 Redis 的 `"6379:6379"` 修改为 `"6380:6379"`
* 修改后，你需要同步修改 `poetize-server/poetry-web/src/main/resources/application.yml` 中的连接端口和密码。

##### 2. 本地数据库密码不同，如何配置/修改？

如果你使用本地已安装的数据库（方式二），但密码与本项目默认的 `123456` 不同，有两种解决途径：

**途径 A：修改后端项目配置文件（推荐）**
编辑 `poetize-server/poetry-web/src/main/resources/application.yml`，修改对应的账号密码和端口：
```yaml
spring:
  datasource:
    username: root
    password: 你的数据库密码
    url: jdbc:mariadb://localhost:3306/poetize?useUnicode=true&characterEncoding=utf-8&serverTimezone=Asia/Shanghai
  redis:
    host: localhost
    port: 6379
    password: 你的Redis密码  # 若无密码则留空
```
*提示：你也可以通过设置环境变量来启动，避免修改代码文件。例如：*
```bash
SPRING_DATASOURCE_PASSWORD=你的数据库密码 SPRING_REDIS_PASSWORD=你的Redis密码 mvn spring-boot:run
```

**途径 B：修改你本地数据库的密码**
如果你想省去修改配置文件的麻烦，可以直接将本地数据库密码修改为 `123456`：
* **MariaDB / MySQL 5.7**:
  ```sql
  ALTER USER 'root'@'localhost' IDENTIFIED BY '123456';
  FLUSH PRIVILEGES;
  ```
* **MySQL 8.0+**（如果遇到加密插件兼容问题）：
  ```sql
  ALTER USER 'root'@'localhost' IDENTIFIED WITH mysql_native_password BY '123456';
  FLUSH PRIVILEGES;
  ```

## 数据库配置

系统默认使用 **MariaDB 11**。MySQL 目前仅作为兼容运行选项，AI 聊天的 RAG 向量检索仅在 MariaDB 11+ 下启用。

> 📖 完整的表结构和字段说明请参考 [数据库设计文档](./数据库设计.md)

### 数据库初始化

本项目在 `poetize-server/sql/` 目录提供两个初始化脚本，二者都会创建业务表和 `ai_knowledge_document` 元数据表，但定位不同：

- **poetry.sql** - 面向 MariaDB 11+，保留 AI 聊天 RAG 的 MariaDB 向量检索能力
- **poetry_old.sql** - 兼容 MySQL 5.7+ 和低版本 MariaDB，系统可运行，但会关闭 RAG 向量检索

**快速选择：**

- 使用本项目 Docker 或 部署脚本 部署 → `poetry.sql`（默认，已配置好所有插件）
- Windows 本地开发 + Docker Desktop → `poetry.sql`（推荐，环境一致）
- 使用本地 MySQL/MariaDB → `poetry_old.sql`（无需插件，兼容性最好；MySQL 下会关闭 RAG）

**初始化命令：**

```bash
# Docker 环境（推荐）
# 先获取数据库密码
ROOT_PWD=$(grep "数据库ROOT密码:" .config/db_credentials.txt | cut -d':' -f2 | tr -d ' ')
docker exec -i poetize-mariadb mariadb -uroot -p${ROOT_PWD} poetize < poetize-server/sql/poetry.sql

# 本地数据库环境（使用自己设置的密码）
mysql -uroot -p poetize < poetize-server/sql/poetry_old.sql
```

### 数据库升级

项目采用“完整建表脚本 + 增量迁移脚本”的方式升级数据库：

- `poetry.sql` / `poetry_old.sql` 表示当前完整建表结构
- `poetize-server/sql/*.sql` 中除这两个之外的时间戳脚本，表示增量迁移
- `poetize -update` 会自动按文件名顺序执行未记录成功的迁移，并写入 `db_migrations`

常用升级命令：

```bash
poetize -update
```

> 详细规则、迁移脚本清单和版本记录机制请参考 [SQL 脚本说明](../poetize-server/sql/README.md)。

### MariaDB 存储引擎插件安装

如果你使用的是自己搭建的 MariaDB 环境（非本项目 Docker），需要手动安装存储引擎插件才能使用 `poetry.sql`。

**1. RocksDB 存储引擎安装**

RocksDB 是一个高性能的键值存储引擎，适合读写密集型应用（如聊天记录表）。

```bash
# Ubuntu/Debian 系统
sudo apt-get update
sudo apt-get install mariadb-plugin-rocksdb

# CentOS/RHEL 系统
sudo yum install MariaDB-rocksdb-engine

# 或使用 dnf（较新的系统）
sudo dnf install MariaDB-rocksdb-engine
```

安装后，在 MariaDB 配置文件中启用：

```ini
# /etc/mysql/conf.d/rocksdb.cnf 或 /etc/my.cnf.d/rocksdb.cnf
[mysqld]
plugin_load_add=rocksdb=ha_rocksdb.so
```

重启 MariaDB 服务：

```bash
sudo systemctl restart mariadb
```

验证安装：

```sql
-- 登录 MariaDB 后执行
SHOW ENGINES;
-- 应该能看到 ROCKSDB 引擎状态为 YES 或 DEFAULT
```

**2. Aria 存储引擎**

Aria 是 MariaDB 的默认存储引擎之一（MyISAM 的改进版），**无需额外安装**，MariaDB 10.0+ 自带。

**3. Docker 环境配置参考**

本项目的 `docker/mysql/Dockerfile` 已经配置好所有存储引擎：

```dockerfile
FROM mariadb:11.8

# 安装 RocksDB 插件
RUN apt-get update && apt-get install -y mariadb-plugin-rocksdb && \
    rm -rf /var/lib/apt/lists/*

# 自动加载 RocksDB 引擎
RUN echo "[mysqld]\nplugin_load_add=rocksdb=ha_rocksdb.so" > /etc/mysql/conf.d/rocksdb.cnf
```

**4. 存储引擎说明**

| 存储引擎          | 用途                             | 特点                 | 是否需要安装          |
| ----------------- | -------------------------------- | -------------------- | --------------------- |
| **InnoDB**  | 通用表（用户、文章等）           | 事务支持、外键、行锁 | ❌ MariaDB/MySQL 自带 |
| **Aria**    | 静态数据表（分类、标签、配置等） | 高速读取、崩溃恢复   | ❌ MariaDB 10.0+ 自带 |
| **RocksDB** | 高并发写入表（聊天记录、历史等） | LSM树结构、压缩存储  | ✅ 需手动安装插件     |

**5. Windows/Linux 开发环境连接数据库**

无论使用什么操作系统，开发环境推荐以下方式：

```bash
# 方案A：完整 Docker 环境（推荐，环境与生产一致）
docker compose up -d mysql redis
# 使用 poetry.sql - 包含所有存储引擎优化

# 方案B：仅使用本地数据库（快速开发）

# 优点：数据库管理工具（如 Navicat）连接更方便
```

## 数据库配置说明

### 数据库选择说明

本项目默认采用MariaDB 11作为数据库，而非MySQL 5.7。这是基于以下考虑：

1. **性能优势** - MariaDB在高并发读写场景下通常表现更佳
2. **开源承诺** - MariaDB保持完全开源，没有商业许可限制
3. **兼容性保证** - 完全兼容MySQL的SQL语法和连接协议
4. **额外特性** - 提供更多存储引擎选项和优化器改进

虽然项目可以使用MySQL运行，但我们推荐使用MariaDB以获得更好的性能和未来的可扩展性。若必须使用MySQL，请参考下方切换步骤进行配置调整。两种数据库的数据文件和表结构完全兼容，可以无缝迁移。

### 从MariaDB切换到MySQL的详细步骤

如需在开发或部署环境中使用MySQL替代MariaDB，按以下步骤操作：

1. **修改Java项目依赖（pom.xml）**

   ```xml
   <!-- 移除MariaDB依赖 -->
   <dependency>
     <groupId>org.mariadb.jdbc</groupId>
     <artifactId>mariadb-java-client</artifactId>
     <version>3.1.4</version>
     <!-- ... -->
   </dependency>

   <!-- 添加MySQL依赖 -->
   <dependency>
     <groupId>mysql</groupId>
     <artifactId>mysql-connector-java</artifactId>
     <version>8.0.33</version>
   </dependency>
   ```

2. **更新Java应用配置（application.yml）**

   ```yaml
   spring:
     datasource:
       # 从这个
       driver-class-name: org.mariadb.jdbc.Driver
       url: jdbc:mariadb://localhost:3306/poetize?useUnicode=true&characterEncoding=utf-8&serverTimezone=Asia/Shanghai

       # 改为这个
       driver-class-name: com.mysql.cj.jdbc.Driver
       url: jdbc:mysql://localhost:3306/poetize?useUnicode=true&characterEncoding=utf-8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true
   ```

3. **修改Docker镜像构建文件（docker/java/Dockerfile）**

   ```Dockerfile
   # 将
   RUN wget -O /app/libs/mariadb-java-client-3.1.4.jar https://repo1.maven.org/maven2/org/mariadb/jdbc/mariadb-java-client/3.1.4/mariadb-java-client-3.1.4.jar

   # 改为
   RUN wget -O /app/libs/mysql-connector-java-8.0.33.jar https://repo1.maven.org/maven2/com/mysql/mysql-connector-j/8.0.33/mysql-connector-j-8.0.33.jar
   ```

4. **更新Docker Compose配置（docker-compose.yml）**

   ```yaml
   # MariaDB服务配置
  mysql:
    # 从这个
    image: mariadb:11.8
    # 改为这个
    image: mysql:8.0

     environment:
       # 从这些环境变量
       - MARIADB_ROOT_PASSWORD=root123
       - MARIADB_DATABASE=poetize 
       - MARIADB_USER=poetize
       - MARIADB_PASSWORD=poetize123

       # 改为这些
       - MYSQL_ROOT_PASSWORD=root123
       - MYSQL_DATABASE=poetize
       - MYSQL_USER=poetize
       - MYSQL_PASSWORD=poetize123
   ```

   还需要修改Java服务环境变量部分：

   ```yaml
   poetize-java:
     # ...
     environment:
       # 修改驱动类名
       - SPRING_DATASOURCE_DRIVER_CLASS_NAME=com.mysql.cj.jdbc.Driver
       # 修改URL前缀
       - SPRING_DATASOURCE_URL=jdbc:mysql://mysql:3306/poetize?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true
   ```


6. **修改my.cnf配置**（MySQL 8.0和MariaDB 11虽然兼容，但有些特定配置可能不同）

   ```ini
   # my.cnf
   [mysqld]
   default-authentication-plugin=mysql_native_password  # MySQL 8.0需要此配置以支持旧密码认证
   # 其他配置...
   ```

7. **将poetry_old.sql覆盖poetry.sql（poetize-server/sql/）**

   ```bash
   rm -f poetry.sql
   # 使用旧脚本（数据表一样，但mysql只能使用InnoDB存储引擎）
   cp poetry_old.sql poetry.sql
   ```

这些修改完成后，系统将使用MySQL而非MariaDB作为数据库引擎。注意，MariaDB对MySQL的某些语法有扩展，如果您的SQL使用了这些扩展特性，切换时可能需要调整。

## 部署方式

本项目推荐使用 `poetize install` 进行自动化部署。该命令集成了环境检测、数据库配置、服务启动及 Nginx/HTTPS 配置，即使你对项目进行了较大的架构修改，也通常不需要额外包装脚本。

### 1. 自动化部署

在项目根目录下执行以下命令：

```bash
# 赋予执行权限
chmod +x poetize

# 交互式部署（适合初次安装，按提示输入即可）
./poetize install

# 非交互式部署（适合生产环境，直接配置域名和邮箱）
./poetize install --domain example.com --email admin@example.com
```

> **提示**：如果对项目进行了较大的架构修改，通常只需要维护 `poetize` 这一个入口脚本。

### 2. 运维与管理入口

部署成功后，脚本会自动安装 `poetize` 全局管理命令，你可以在**任意目录**下直接执行命令：

```bash
poetize
```

执行后会进入 **Control Center (控制中心)** 交互式管理菜单：

|:---:|---|---|

### 3. 重要部署提示

> [!WARNING]
> **切勿绕过 `poetize install` 使用原生 Docker 命令**：
> 部署脚本不仅仅是启动容器，它还负责生成 `default.http.conf`、`default.https.conf` 以及数据库凭据。直接运行 `docker compose up` 可能会导致 Nginx 配置缺失或服务无法正常启动。

#### HTTPS 与生产环境登录

> [!IMPORTANT]
> **生产环境必须启用 HTTPS**：
> 本项目的前后端均使用了 **Web Crypto API** 进行密码加密和身份验证。浏览器安全策略规定，该 API 仅在 `localhost` 或 `HTTPS` 环境下可用。
> - 如果你在公网服务器上部署且**未启用 HTTPS**，将**无法成功登录**后台。
> - 在本地开发环境（`localhost`），可以直接使用 HTTP。

若需调整 Nginx 配置，建议修改后使用 `poetize -restart` 重新应用。
