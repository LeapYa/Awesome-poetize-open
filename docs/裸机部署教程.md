# 裸机部署教程（不使用 Docker）

本文档介绍如何在 Linux 服务器上**不使用 Docker**，手动安装各组件来部署 POETIZE 博客系统。

## 适用场景

- 服务器不支持或不想安装 Docker
- 希望对每个组件有完全控制
- 学习了解项目各组件的工作原理

> **提示**：如果你的服务器支持 Docker，推荐使用一键脚本部署，参见 [README.md](../README.md)。

## 前提条件

| 项目 | 要求 |
|------|------|
| 服务器 | 2 核 CPU / 2GB 内存 / 20GB 磁盘（最低），推荐 4GB+ 内存 |
| 操作系统 | Ubuntu 22.04+、Debian 12+、CentOS 9+ |
| 域名 | 可选，上线需要绑定域名 |
| 网络 | 开放 80（HTTP）、443（HTTPS）端口 |

## 1. 安装基础环境

### 1.1 更新系统

```bash
# Ubuntu / Debian
sudo apt update && sudo apt upgrade -y

# CentOS / RHEL
sudo dnf update -y
```

### 1.2 安装 JDK 25

推荐使用 [SDKMAN](https://sdkman.io/) 安装，方便管理多版本：

```bash
# 安装 SDKMAN
curl -s "https://get.sdkman.io" | bash
source "$HOME/.sdkman/bin/sdkman-init.sh"

# 安装 JDK 25（查看可用版本：sdk list java）
sdk install java 25.0.2-open

# 验证
java -version
```

### 1.3 安装 Maven 3.9+

```bash
# 使用 SDKMAN（推荐）
sdk install maven

# 或 Ubuntu / Debian
sudo apt install -y maven

# 验证
mvn -v
```

### 1.4 安装 Node.js 20+

前端构建需要 Node.js：

```bash
# 下载并安装 nvm：
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.3/install.sh | bash

# 代替重启 shell
\. "$HOME/.nvm/nvm.sh"

# 下载并安装 Node.js：
nvm install 24
```

### 1.5 安装 MariaDB 11

```bash
# Ubuntu / Debian（使用 MariaDB 官方仓库安装最新 11.8）
sudo apt install -y software-properties-common curl
curl -LsS https://dlm.mariadb.com/enterprise-release-helpers/mariadb_es_repo_setup | sudo bash -s -- --mariadb-server-version="mariadb-11.8"
sudo apt install -y mariadb-server mariadb-client

# CentOS / RHEL
sudo dnf install -y mariadb-server mariadb

# 启动并设置开机自启
sudo systemctl enable --now mariadb

# 安全初始化
sudo mariadb-secure-installation
```

> **可选**：本项目部分表支持 RocksDB 存储引擎以获得更好的性能。如需启用，安装 RocksDB 插件：
> ```bash
> sudo apt install -y mariadb-plugin-rocksdb
> echo -e "[mysqld]\nplugin_load_add=rocksdb=ha_rocksdb.so" | sudo tee /etc/mysql/mariadb.conf.d/rocksdb.cnf
> sudo systemctl restart mariadb
> sudo mariadb -e "SHOW ENGINES;" | grep -i rocksdb
> ```
> 未安装 RocksDB 也可正常运行，只需在导入 SQL 时使用 `poetry_old.sql`（全部使用 InnoDB 引擎）。

### 1.6 安装 Redis 7

```bash
# Ubuntu / Debian
curl -fsSL https://packages.redis.io/gpg | sudo gpg --dearmor -o /usr/share/keyrings/redis-archive-keyring.gpg
sudo chmod 644 /usr/share/keyrings/redis-archive-keyring.gpg
echo "deb [signed-by=/usr/share/keyrings/redis-archive-keyring.gpg] https://packages.redis.io/deb $(lsb_release -cs) main" | sudo tee /etc/apt/sources.list.d/redis.list
sudo apt-get update
sudo apt-get install redis

# CentOS / RHEL
sudo yum install redis
sudo systemctl enable redis
sudo systemctl start redis
```

配置 Redis 密码：

```bash
# 编辑 Redis 配置
sudo nano /etc/redis/redis.conf

# 找到 # requirepass，取消注释并设置密码
requirepass your_redis_password

# 重启 Redis
sudo systemctl restart redis-server
```

### 1.7 安装 OpenResty

项目使用 Lua 脚本在 Nginx access 阶段直接查 Redis 拦截恶意 IP（详见 [5.4](#54-启用-ip-黑名单openresty--lua--redis)），需要 OpenResty（Nginx + LuaJIT）才能执行 `access_by_lua_file`。**直接装 OpenResty，不要装普通 Nginx**，否则后续 IP 黑名单功能不可用。

OpenResty 是 Nginx 的超集，配置文件语法完全兼容。

```bash
# Ubuntu / Debian
wget -O - https://openresty.org/package/pubkey.gpg | sudo gpg --dearmor -o /usr/share/keyrings/openresty-archive-keyring.gpg
sudo chmod 644 /usr/share/keyrings/openresty-archive-keyring.gpg
echo "deb [signed-by=/usr/share/keyrings/openresty-archive-keyring.gpg] http://openresty.org/package/ubuntu $(lsb_release -cs) main" | sudo tee /etc/apt/sources.list.d/openresty.list
sudo apt update
sudo apt install -y openresty

# CentOS / RHEL（参考 https://openresty.org/cn/linux-packages.html）
sudo yum install -y yum-utils
sudo yum-config-manager --add-repo https://openresty.org/package/centos/openresty.repo
sudo yum install -y openresty

# 启动并设置开机自启
sudo systemctl enable --now openresty

# 验证
sudo systemctl status openresty
curl -I http://localhost  # 应返回 200 或 404（默认欢迎页或 404）
```

> **配置文件路径**：OpenResty 主配置在 `/usr/local/openresty/nginx/conf/nginx.conf`，后续所有 Nginx 配置编辑都在此目录下进行。

### 1.8 安装运行时工具依赖

后端运行时会用到健康检查工具、媒体转换器、WebP 工具和 `cn-font-split`。Node.js/npm 已在上一步安装；`cn-font-split` 依赖需要项目代码，后面部署 JAR 时会安装到 `/opt/poetize/split_font`。

```bash
# Ubuntu / Debian
sudo apt install -y curl netcat-openbsd ffmpeg webp

# CentOS / RHEL
sudo dnf install -y epel-release curl nmap-ncat
sudo dnf install -y https://mirrors.rpmfusion.org/free/el/rpmfusion-free-release-$(rpm -E %rhel).noarch.rpm
sudo dnf install -y ffmpeg libwebp-tools

# 验证
curl --version
command -v nc || command -v ncat
ffmpeg -version
cwebp -version
dwebp -version
```

## 2. 初始化数据库

### 2.1 创建数据库和用户

```bash
sudo mariadb -u root -p
```

```sql
-- 创建数据库（使用 utf8mb4 编码）
CREATE DATABASE poetize CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

-- 创建用户并授权
CREATE USER 'poetize'@'localhost' IDENTIFIED BY 'your_db_password';
GRANT ALL PRIVILEGES ON poetize.* TO 'poetize'@'localhost';
FLUSH PRIVILEGES;
EXIT;
```

### 2.2 导入初始化 SQL

```bash
# 克隆项目（如果还没有）
git clone https://github.com/LeapYa/awesome-poetize-open.git
cd awesome-poetize-open

# 导入初始化 SQL（首次安装只需导入这一个文件）
mariadb -u poetize -p poetize < poetize-server/sql/poetry_old.sql
# 如果已安装 RocksDB 引擎，可使用 poetry.sql（history_info 表使用 RocksDB 引擎）
# mariadb -u poetize -p poetize < poetize-server/sql/poetry.sql
```

> **说明**：`poetize-server/sql/` 目录下的其他时间戳 SQL 文件（如 `202507220125.sql`）是**增量升级脚本**，仅在从旧版本升级时使用，首次安装无需导入。

### 4.3 配置 systemd 守护进程

创建 systemd 服务文件实现开机自启和后台运行（环境变量请根据你个人的实际配置修改）：

```bash
sudo tee /etc/systemd/system/poetize.service > /dev/null << 'EOF'
[Unit]
Description=POETIZE Blog Backend
After=network.target mariadb.service redis-server.service
Requires=mariadb.service redis-server.service

[Service]
Type=simple
# Ubuntu/Debian 使用 www-data，CentOS/RHEL 改为 nginx 或 root
User=www-data
Group=www-data
WorkingDirectory=/opt/poetize
ExecStart=/usr/bin/java \
  --enable-preview \
  -Xmx1024m -Xms512m \
  -XX:MaxMetaspaceSize=256m \
  -XX:+UseZGC \
  -XX:+ExitOnOutOfMemoryError \
  -jar /opt/poetize/poetize-server-exec.jar
Restart=on-failure
RestartSec=10

# 环境变量（根据你个人的实际配置修改）
# ==================================================
# 数据库连接（根据实际数据库类型修改 URL）
# MariaDB: jdbc:mariadb://localhost:3306/poetize?useUnicode=true&characterEncoding=utf-8&serverTimezone=Asia/Shanghai
# MySQL:   jdbc:mysql://localhost:3306/poetize?useUnicode=true&characterEncoding=utf-8&serverTimezone=Asia/Shanghai
Environment=SPRING_DATASOURCE_URL=jdbc:mariadb://localhost:3306/poetize?useUnicode=true&characterEncoding=utf-8&serverTimezone=Asia/Shanghai
Environment=SPRING_DATASOURCE_USERNAME=poetize
Environment=SPRING_DATASOURCE_PASSWORD=your_db_password

# Redis 连接
Environment=SPRING_REDIS_HOST=localhost
Environment=SPRING_REDIS_PORT=6379
Environment=SPRING_REDIS_PASSWORD=your_redis_password

# 站点配置
Environment=SITE_URL=http://your-domain.com

# 文件上传与预渲染目录
Environment=LOCAL_UPLOADURL=/var/www/uploads/
Environment=PRERENDER_TEMPLATE_PATH=/var/www/poetize/index.html
Environment=PRERENDER_OUTPUT_ROOT=/var/www/poetize/prerender
Environment=PRERENDER_ADMIN_TEMPLATE_PATH=/var/www/admin/index.html
Environment=PRERENDER_ADMIN_OUTPUT_ROOT=/var/www/admin/prerender

# 前端AES密钥（前端逆向可被看到）
Environment=POETIZE_AES_KEY=sarasarasarasara
Environment=TOKEN_SECRET_KEY=your_super_secure_random_key_here_at_least_32_chars
# ==================================================

[Install]
WantedBy=multi-user.target
EOF
```

部署 JAR 并启动：


## 5. 配置 Nginx 反向代理

### 5.1 创建 Nginx 配置

> **⚠️ 重要**：以下配置中的 `your-domain.com` 需要替换为你自己的域名。如果暂时没有域名，可以先用服务器 IP 或 `localhost` 代替。

```bash
# 创建站点配置目录（OpenResty 默认不带 sites-available/enabled，需手动建）
sudo mkdir -p /usr/local/openresty/nginx/conf/{sites-available,sites-enabled}

# 在 OpenResty 主配置的 http { } 块内添加 Lua 路径声明、空 UA 识别 map 和 sites-enabled 引用
sudo sed -i '/^http {/a\    # 空 User-Agent 识别（爬虫/扫描器典型特征：抹除UA）\n    map $http_user_agent $is_empty_user_agent {\n        default 0;\n        "" 1;\n        "-" 1;\n    }\n    lua_package_path "/usr/local/openresty/nginx/lua/?.lua;;";\n    include /usr/local/openresty/nginx/conf/sites-enabled/*;' /usr/local/openresty/nginx/conf/nginx.conf

# 创建站点配置
sudo tee /usr/local/openresty/nginx/conf/sites-available/poetize > /dev/null << 'NGINX_CONF'
# Upstream：定义后端地址并启用 keepalive 连接复用
# keepalive 值需 ≤ 后端 Druid 连接池 max-active（默认 64）
upstream poetize-java {
    server 127.0.0.1:8081 max_fails=3 fail_timeout=30s;
    keepalive 64;
    keepalive_requests 10000;
    keepalive_timeout 60s;
}

server {
    listen 80;
    # ⬇️ 替换为你自己的域名
    server_name your-domain.com www.your-domain.com;
    charset utf-8;

    # 安全头
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-XSS-Protection "1; mode=block" always;

    # 请求大小限制
    client_max_body_size 100M;

    # gzip压缩，如果需要Brotli压缩自行编译并添加相关代码
    gzip on;
    gzip_types text/plain text/css application/json application/javascript text/xml application/xml;
    gzip_min_length 256;

    # ===== 后台管理前端 =====
    location ^~ /admin/assets/ {
        alias /var/www/admin/assets/;
        expires 30d;
    }

    location ^~ /admin {
        alias /var/www/admin;
        index index.html;
        try_files $uri $uri/ /prerender/index.html @admin_fallback;
    }

    location = /admin/index.html {
        root /var/www;
        try_files /admin/prerender/index.html /admin/index.html =404;
        expires -1;
        add_header Cache-Control "no-store, no-cache, must-revalidate";
    }

    location @admin_fallback {
        root /var/www;
        try_files /admin/prerender/index.html /admin/index.html =404;
    }

    # ===== API 反向代理 =====
    location ^~ /api/ {
        proxy_pass http://poetize-java/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_http_version 1.1;
        proxy_set_header Connection "";
        proxy_read_timeout 900s;
    }

    # Java后端用户相关 API
    location ~ ^/user/(login|register|logout|updateUserInfo|getCode|getCodeForBind|updateUserSecretInfo|bindingUserSecretInfo|getUserInfo|listUser|saveUser|updatePassword|updateAdminInfo|deleteUsers|getAdminUserInfo|updateAdminConfig) {
        proxy_pass http://poetize-java;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_http_version 1.1;
        proxy_set_header Connection "";
    }

    # OAuth 路由
    location ^~ /login/ {
        rewrite ^/login/(.*)$ /oauth/login/$1 break;
        proxy_pass http://poetize-java;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_http_version 1.1;
        proxy_set_header Connection "";
    }

    location ^~ /callback/ {
        rewrite ^/callback/(.*)$ /oauth/callback/$1 break;
        proxy_pass http://poetize-java;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_http_version 1.1;
        proxy_set_header Connection "";
    }

    # WebSocket（聊天室）
    location ^~ /ws/im {
        proxy_pass http://poetize-java/ws/im;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_read_timeout 600s;
    }

    # SEO 相关
    location = /manifest.json {
        proxy_pass http://127.0.0.1:8081/seo/manifest.json;
    }
    location = /robots.txt {
        proxy_pass http://127.0.0.1:8081/seo/robots.txt;
    }
    location = /favicon.ico {
        proxy_pass http://127.0.0.1:8081/seo/favicon.ico;
    }

    # 静态资源（上传的文件）
    location /static {
        alias /var/www/uploads;
        try_files $uri @fallback_static;
        expires 30d;
        add_header Cache-Control "public, no-transform";
    }
    location @fallback_static {
        root /var/www/poetize;
        try_files /static$uri =404;
    }

    # 聊天室静态资源
    location /im/static/ {
        alias /var/www/poetize/static/;
        expires 30d;
        add_header Cache-Control "public, no-transform";
    }

    # ===== 安全防护 =====

    # 拦截空 User-Agent 请求（爬虫/扫描器典型特征）
    # 返回 403 走统一错误处理，请求不会到达后端，避免污染访问统计
    if ($is_empty_user_agent) {
        return 403;
    }

    # 防止目录遍历攻击
    location ~* \.\./  {
        return 403;
    }

    # 禁止访问隐藏文件（排除 .well-known 以支持 SSL 证书验证）
    location ~ /\.(?!well-known/) {
        return 403;
    }

    # 禁止访问敏感文件类型（conf 为项目配置文件常见后缀）
    location ~* \.(htaccess|htpasswd|env|config|conf|ini|log|sql|bak|backup|old|tmp|swp|swo)$ {
        return 403;
    }

    # 拦截 PHP 请求（本站非 PHP，.php 请求必为扫描器探测）
    # 排除 /static/articleFile/ 以保留用户上传的 PHP 类附件走强制下载规则
    location ~* ^(?!/static/articleFile/).*\.php$ {
        return 444;
    }

    # 拦截 WordPress 相关路径（本站非 WordPress，所有 wp-* 请求均为扫描器探测）
    location ~* ^/(wp-admin|wp-login|wp-content|wp-includes|wp-json|wp-config) {
        return 444;
    }

    # 拦截其他动态脚本后缀（本站为 Java + Vue 前后端分离，不存在 ASP/JSP/CGI/Python/Perl/Ruby 脚本）
    # 排除 /static/articleFile/ 以保留用户上传的脚本类附件走强制下载规则
    location ~* ^(?!/static/articleFile/).*\.(asp|aspx|jsp|cgi|pl|py|rb)$ {
        return 444;
    }

    # 拦截常见管理工具与状态页探测路径
    location ~* ^/(phpmyadmin|pma|adminer|mysql|server-status|server-info|cgi-bin) {
        return 444;
    }

    # ===== SEO 预渲染页面（纯 Nginx 版本）=====
    #
    # 优先读取 Java 后端生成的 prerender 静态 HTML。
    # 如果没有生成对应预渲染文件，则回退到 Vue SPA。
    location = / {
        root /var/www/poetize;
        try_files /prerender/home/index.html @spa_fallback;
    }

    # 旧版SEO入口兼容：归档页归到首页，分类/标签页归到分类导航页
    location ~ ^/archives/?$ {
        return 301 /$is_args$args;
    }
    location ~ ^/(categories|tags)/?$ {
        return 301 /sort$is_args$args;
    }

    location ~ ^/article/([a-zA-Z-]+)/([A-Za-z0-9-]+)$ {
        root /var/www/poetize;
        try_files /prerender/article/$2/index-$1.html /prerender/article/$2/index.html @spa_fallback;
    }

    location ~ ^/article/([A-Za-z0-9-]+)$ {
        root /var/www/poetize;
        try_files /prerender/article/$1/index.html @spa_fallback;
    }

    location = /sort {
        root /var/www/poetize;
        try_files /prerender/sort/index.html @spa_fallback;
    }

    location ~ ^/sort/([0-9]+)$ {
        root /var/www/poetize;
        try_files /prerender/sort/$1/$arg_labelId/index.html /prerender/sort/$1/index.html @spa_fallback;
    }

    location @spa_fallback {
        root /var/www/poetize;
        try_files $uri $uri/ /index.html;
    }

    # ===== 主站前端（SPA 回退） =====
    location / {
        root /var/www/poetize;
        index index.html;
        try_files $uri $uri/ /index.html;

        location = /index.html {
            expires -1;
            add_header Cache-Control "no-store, no-cache, must-revalidate";
        }
    }

    # Let's Encrypt 验证
    location /.well-known/acme-challenge/ {
        root /var/www/html;
    }
}
```

### 5.4 启用 IP 黑名单（OpenResty + Lua + Redis）

> 1.7 已安装 OpenResty，5.1 已在主配置中声明 `lua_package_path`。本节只需部署 Lua 脚本并在站点配置中接入即可。

恶意爬虫、爆破、CC 攻击等场景下，IP 黑名单是第一道防线。Java 后端在检测到恶意行为时自动写入封禁 IP 到 Redis，OpenResty 在请求到达后端前就完成拦截，被拦请求不消耗任何后端资源。

#### 5.4.1 部署 Lua 脚本

```bash
# 1. 创建 Lua 脚本目录
sudo mkdir -p /usr/local/openresty/nginx/lua

# 2. 复制项目仓库中的 ip_blacklist.lua
sudo cp docker/nginx/lua/ip_blacklist.lua /usr/local/openresty/nginx/lua/ip_blacklist.lua

# 3. 创建 Redis 连接配置文件（密码独立存放，便于权限管控）
sudo tee /usr/local/openresty/nginx/lua/redis_config.lua > /dev/null << 'LUA_EOF'
-- Redis 连接配置（仅此文件含密码，权限设为 600）
return {
    host = "127.0.0.1",
    port = 6379,
    password = "your_redis_password",  -- 替换为你的 Redis 密码，无密码则留空字符串
    db = 0
}
LUA_EOF

# 4. 修改 ip_blacklist.lua 加载本地 Redis 配置（裸机无环境变量机制）
#    在脚本开头的 REDIS_HOST 定义处，替换为：
#    local redis_config = require "redis_config"
#    local REDIS_HOST = redis_config.host
#    local REDIS_PORT = redis_config.port
#    local REDIS_PASSWORD = redis_config.password
#    local REDIS_DB = redis_config.db

# 5. 修改 IP 获取方式（裸机无 CDN 时用 $remote_addr）
#    在 get_client_ip() 函数中：
#    local ip = ngx.var.remote_addr  -- 替换原 ngx.var.real_client_ip

# 6. 保护配置文件权限（仅 root 可读，避免密码泄露）
sudo chmod 600 /usr/local/openresty/nginx/lua/redis_config.lua
sudo chown root:root /usr/local/openresty/nginx/lua/redis_config.lua
```

#### 5.4.2 在 Nginx 配置中接入 Lua 拦截

编辑 `/usr/local/openresty/nginx/conf/sites-available/poetize`，在 `server { }` 块内（建议放在 `charset` 之后、`location` 之前）插入：

```nginx
# IP 黑名单检查 - Lua 脚本直接查 Redis（OpenResty）
# 在 access 阶段执行，命中黑名单的 IP 直接返回 403，连 HTML 源码也不会返回
# fail-open：Redis 不可用时放行，避免误伤全站
access_by_lua_file /usr/local/openresty/nginx/lua/ip_blacklist.lua;

# 403 处理器（Lua 脚本自己也会返回 403，此处兜底其他 403 场景）
error_page 403 = @handle_403;

location @handle_403 {
    default_type text/html;
    return 403 "<!DOCTYPE html><html><head><meta charset=\"utf-8\"><title>403 Forbidden</title></head><body><h1>403 Forbidden</h1><p>访问被拒绝。</p></body></html>";
}
```

测试并重载：

```bash
sudo openresty -t
sudo systemctl reload openresty
```

#### 5.4.3 IP 黑名单工作原理

**Lua 脚本执行流程**（每个请求到达 OpenResty 时）：

1. 从 `ngx.var.remote_addr` 获取客户端真实 IP
2. 通过连接池复用 Redis 连接（避免每请求新建），执行 `EXISTS poetize:security:blacklist:{ip}`
3. 命中则直接返回 403（连 HTML 源码也不返回，防止被封禁 IP 抓取网站内容）
4. Redis 不可用时 fail-open 放行，避免误伤全站

**性能**：连接池复用 + Redis 本地查询，单次检查约 **0.4ms**，几乎无感知。

**封禁规则**：Java 后端在以下场景自动写入黑名单（默认 TTL 24 小时，可在后台管理配置）：

- 频繁触发 WAF 规则（SQL 注入、XSS、路径穿越等）
- 登录爆破（连续失败超阈值）
- 异常高频请求（CC 攻击特征）

**手动管理**：在后台管理 → 安全中心可查看/解除封禁 IP。

#### 5.4.4 CDN 场景下的真实 IP 获取

如果服务器前面套了 CDN（如 Cloudflare、阿里云 CDN），`$remote_addr` 拿到的是 CDN 节点 IP，而非真实客户端 IP，黑名单会失效。需在 `server { }` 块内添加 `set_real_ip_from` 指令：

```nginx
# Cloudflare IP 段（示例，完整列表见 https://www.cloudflare.com/ips/）
set_real_ip_from 173.245.48.0/20;
set_real_ip_from 103.21.244.0/22;
set_real_ip_from 103.22.200.0/22;
# ... 其他 CDN 的 IP 段

real_ip_header CF-Connecting-IP;  # Cloudflare 专用
# real_ip_header X-Forwarded-For;  # 通用 CDN
```

配置后 OpenResty 会自动把 `$remote_addr` 替换为真实客户端 IP，Lua 脚本无需改动。
