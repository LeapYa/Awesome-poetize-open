# 宝塔面板部署教程（不使用Docker）

本文档介绍如何使用宝塔面板（BaoTa Panel）**直接在服务器上部署** POETIZE 博客系统，**完全不使用 Docker**。

## 适用场景

- 喜欢通过 Web 界面管理服务器，无需频繁操作命令行
- 服务器已安装宝塔面板或计划安装宝塔
- 希望对所有服务有完整的可视化控制
- 追求直接部署、易于维护的方案

> **提示**：相比 Docker 一键脚本，此方案提供更多灵活性和可视化管理，但需要手动配置各个环节。

## 前提条件

| 项目 | 要求 |
|------|------|
| 服务器 | 2 核 CPU / 2GB 内存 / 20GB 磁盘（最低），推荐 4GB+ 内存 |
| 操作系统 | Ubuntu 20.04+、Debian 11+、CentOS 7/8+ |
| 域名 | 可选，上线需要绑定域名 |
| 网络 | 开放 80（HTTP）、443（HTTPS）端口；宝塔面板随机高位端口（见安装输出） |
| 宝塔面板 | 已安装（如未安装，见[宝塔安装](#1安装宝塔面板)） |

## 1. 安装宝塔面板

如果服务器未安装宝塔面板，先按以下步骤安装。

### 1.1 一键安装脚本

在服务器上以 root 用户执行：

```bash
if [ -f /usr/bin/curl ];then curl -sSO https://download.bt.cn/install/install_panel.sh;else wget -O install_panel.sh https://download.bt.cn/install/install_panel.sh;fi;bash install_panel.sh ed8484bec
```

安装完成后，会输出登录信息。**重要：请妥善保管这些信息**：
- **外网面板地址**：`https://xx.xx.xx.xx:xxxxx/xxxxx`（HTTPS + 随机端口）
- **内网面板地址**：用于内网访问
- **用户名**：见输出
- **密码**：见输出

### 1.2 登录宝塔面板

1. 使用浏览器打开安装输出中的外网面板地址（注意是 HTTPS）
2. 输入用户名和密码登录
3. 首次登录会要求你绑定宝塔官网账号，可以点击暂不绑定

ps：以前绑定宝塔官网账号是强制的，感谢1panel

## 2. 安装运行环境

在宝塔面板中安装必要的运行环境。

### 2.1 通过宝塔软件商店安装

在宝塔左侧菜单选择 **软件商店**，依次安装以下环境：

#### 2.1.1 安装 JDK 25（Java 环境）

> **注意**：宝塔软件商店目前最高只提供 JDK 21，而本项目需要 JDK 25，因此需要手动安装。

在宝塔终端执行以下命令手动安装 JDK 25：

```bash
# 下载 JDK 25（Adoptium/Eclipse Temurin 发行版）
cd /usr/local
curl -LO https://github.com/adoptium/temurin25-binaries/releases/download/jdk-25%2B9/OpenJDK25U-jdk_x64_linux_hotspot_25_9.tar.gz

# 解压
tar -xzf OpenJDK25U-jdk_x64_linux_hotspot_25_9.tar.gz

# 配置环境变量
cat >> /etc/profile << 'EOF'
export JAVA_HOME=/usr/local/jdk-25+9
export PATH=$JAVA_HOME/bin:$PATH
EOF

# 使环境变量生效
source /etc/profile

# 清理下载文件
rm -f OpenJDK25U-jdk_x64_linux_hotspot_25_9.tar.gz
```

**手动验证**（在宝塔终端执行）：

```bash
java -version
# 应输出 openjdk version "25" 或类似信息
javac -version
```

> **提示**：如果下载速度较慢，可以到 [Adoptium 官网](https://adoptium.net/temurin/releases/?version=25) 手动下载后上传到服务器 `/usr/local` 目录，再执行解压和环境变量配置步骤。

#### 2.1.2 安装 Maven 3.9+（项目构建工具）

> 宝塔软件商店中没有独立的 Maven，由于 JDK 25 也是手动安装的，Maven 同样需要手动安装。

在宝塔终端执行以下命令：

```bash
cd /usr/local
curl -LO https://dlcdn.apache.org/maven/maven-3/3.9.9/binaries/apache-maven-3.9.9-bin.tar.gz
tar -xzf apache-maven-3.9.9-bin.tar.gz
rm -f apache-maven-3.9.9-bin.tar.gz

cat >> /etc/profile << 'EOF'
export MAVEN_HOME=/usr/local/apache-maven-3.9.9
export PATH=$MAVEN_HOME/bin:$PATH
EOF

source /etc/profile
```

**手动验证**：

```bash
mvn -v
```

#### 2.1.3 安装 Node.js 20+（前端构建）

1. 在软件商店搜索 **Node.js版本管理器**，点击 **安装**
2. 安装完成后，在左侧菜单找到 **Node.js版本管理器**，进入管理界面
3. **更新版本列表**：点击页面右上角的 **更新版本列表** 按钮，确保获取到最新的 Node.js 版本列表
4. 在版本列表中选择 **v20.x** 或更新的稳定版（如 v22.x、v24.x），点击 **安装**
5. 安装完成后，点击上方的 **命令行版本** 的下拉框，选择我们刚才安装的版本（如v20.x），设为命令行默认版本

> 这个Node.js可以追新，Node每隔6个月发布一个LTS版本（长期支持版本，也就是稳定版），建议使用LTS版本，选择哪个版本都无所谓，只要是LTS版本即可。

**手动验证**：

```bash
node -v
npm -v
```

#### 2.1.4 安装 MariaDB 11（数据库）

1. 在软件商店搜索 **MySQL**
2. 点击**安装**，选择版本 **mysql mariadb_11.8.2**（或 **mysql 8.0+**）
3. 选择 **极速安装**，等待安装完成
4. 安装完成后，在宝塔左侧菜单选择 **数据库**，点击 **root密码** 查看或修改 root 密码（记好它）

**手动验证**：

```bash
mysql --version
```

#### 2.1.5 安装 Redis（缓存服务）

1. 在软件商店搜索 **Redis**
2. 选择版本 **7.x** 或更新
3. 点击 **安装**

> **Redis 默认无密码**：宝塔安装的 Redis 默认不设置密码（`requirepass` 被注释），本教程的 `.env` 配置中 `SPRING_REDIS_PASSWORD` 留空即可。如需设置密码，在软件商店找到 Redis → **设置** → **配置修改**，找到 `requirepass` 行取消注释并设置密码，重启 Redis 后同步修改 `.env` 中的 `SPRING_REDIS_PASSWORD`。

**手动验证**：

```bash
redis-cli --version
```

#### 2.1.6 安装 Nginx（Web 服务器）

1. 在软件商店搜索 **Nginx**
2. 选择版本 **1.26+**
3. 点击 **安装**

**手动验证**：

```bash
nginx -v
```

#### 2.1.7 安装 Git（版本控制）

在宝塔终端执行：

```bash
# 根据操作系统选择对应的命令
# Ubuntu / Debian
sudo apt install -y git

# CentOS 7
sudo yum install -y git

# CentOS 8+
sudo dnf install -y git
```

> 如果软件商店中有 Git 也可以通过商店安装，但命令行安装更可靠。

#### 2.1.8 安装运行时工具依赖

后端运行时会用到健康检查工具、媒体转换器、WebP 工具和 `cn-font-split`。Node.js/npm 已在前面安装；`cn-font-split` 依赖需要项目代码，后面部署 Java 后端前会在 `/home/poetize/split_font` 中安装。

在宝塔终端执行：

```bash
# Ubuntu / Debian
sudo apt install -y curl netcat-openbsd ffmpeg webp

# CentOS 7
sudo yum install -y epel-release curl nmap-ncat
sudo yum install -y https://mirrors.rpmfusion.org/free/el/rpmfusion-free-release-7.noarch.rpm
sudo yum install -y ffmpeg libwebp-tools

# CentOS 8+
sudo dnf install -y epel-release curl nmap-ncat
sudo dnf install -y https://mirrors.rpmfusion.org/free/el/rpmfusion-free-release-$(rpm -E %rhel).noarch.rpm
sudo dnf install -y ffmpeg libwebp-tools
```

### 2.2 验证所有环境

在宝塔终端执行以下命令验证所有环境已正确安装：

```bash
echo "=== 检查 JDK ===" && java -version
echo "=== 检查 Maven ===" && mvn -v
echo "=== 检查 Node.js ===" && node -v && npm -v
echo "=== 检查 MySQL ===" && mysql --version
echo "=== 检查 Redis ===" && redis-cli --version
echo "=== 检查 Nginx ===" && nginx -v
echo "=== 检查 Git ===" && git --version
echo "=== 检查健康检查工具 ===" && curl --version && (command -v nc || command -v ncat)
echo "=== 检查媒体处理工具 ===" && ffmpeg -version && cwebp -version && dwebp -version
```

确认所有命令都返回版本号。

## 3. 部署 POETIZE 博客系统

### 3.1 准备项目目录

在宝塔面板中：

1. 左侧菜单选择 **文件**
2. 定位到 `/home` 目录
3. 点击 **新建文件夹**，名称为 `poetize`

### 3.2 克隆项目代码

在宝塔终端执行：

```bash
cd /home/poetize
git clone --depth 1 https://github.com/LeapYa/awesome-poetize-open.git .
```

### 3.3 创建数据库

在宝塔面板左侧菜单选择 **数据库**：

1. 点击 **添加数据库**
2. 填写信息：
   - **数据库名**：`poetize`
   - **用户名**：`poetize`（默认与数据库名相同）
   - **密码**：随机生成或自定义（记好密码）
   - **字符集**：`utf8mb4`
3. 点击 **确定**

> 记好这个密码，后续配置 Java 应用时需要用到。

### 3.4 导入数据库初始化脚本

在宝塔面板 **数据库** 中：

1. 选择 `poetize` 数据库
2. 点击 **导入**
3. 选择初始化脚本导入：
   - 如果使用 **MariaDB 11+**：选择 `/home/poetize/poetize-server/sql/poetry.sql`
   - 如果使用 **MySQL 8.0+** 或低版本 MariaDB：选择 `/home/poetize/poetize-server/sql/poetry_old.sql`
4. 点击 **导入**

完成后，数据库初始化就完成了（包括版本管理表和所有业务表）。

> **后续升级**：当项目更新后，数据库结构可能发生变化，需要手动执行 `poetize-server/sql/` 目录下的增量迁移脚本。请参考 [6.6 更新项目版本](#66-更新项目版本) 中的数据库迁移步骤。

### 3.5 编译前端项目

#### 3.5.1 编译主站前端（poetize-web）

在宝塔终端执行：

```bash
cd /home/poetize/poetize-web

# 安装依赖
npm install

# 构建生产版本
npm run build

# 将构建后的文件复制到 Nginx 静态目录
sudo mkdir -p /www/wwwroot/poetize
sudo cp -r dist/* /www/wwwroot/poetize/
sudo mkdir -p /www/wwwroot/poetize/static
sudo chown -R www:www /www/wwwroot/poetize
```

#### 3.5.2 编译后台管理前端（poetize-admin）

在宝塔终端执行：

```bash
cd /home/poetize/poetize-admin

# 安装依赖
npm install

# 构建生产版本（Vue 2 项目）
npm run build

# 将构建后的文件复制到 Nginx 静态目录
sudo mkdir -p /www/wwwroot/poetize/admin
sudo cp -r dist/* /www/wwwroot/poetize/admin/
sudo chown -R www:www /www/wwwroot/poetize/admin
```

> **注意**：前端构建较耗时，请耐心等待（通常 5-15 分钟）。

### 3.6 编译 Java 后端应用

#### 3.6.1 安装 cn-font-split 字体分割依赖

在宝塔终端执行：

```bash
cd /home/poetize/split_font
npm install --omit=dev
```

#### 3.6.2 编译 Java 后端

在宝塔终端执行：

```bash
cd /home/poetize/poetize-server

# 使用 Maven 构建
mvn clean package -DskipTests

# 等待编译完成（首次编译较慢，可能需要 10-20 分钟）
```

编译成功后，会生成 JAR 文件：

```
poetize-server/poetry-web/target/poetize-server-exec.jar
```

### 3.7 配置环境变量

在宝塔终端执行以下命令创建 `.env` 文件，用于存储数据库、Redis 和 JVM 参数配置：

```bash
cat > /home/poetize/.env << 'EOF'
# ========== 数据库配置 ==========
# 数据库用户名
SPRING_DATASOURCE_USERNAME=poetize

# 数据库密码（修改为你在步骤 3.3 中设置的密码）
SPRING_DATASOURCE_PASSWORD=your_db_password

# 数据库连接 URL - 根据使用的数据库类型选择：
# 如果使用 MariaDB：
SPRING_DATASOURCE_URL=jdbc:mariadb://localhost:3306/poetize?useUnicode=true&characterEncoding=utf-8&serverTimezone=Asia/Shanghai
SPRING_DATASOURCE_DRIVER_CLASS_NAME=org.mariadb.jdbc.Driver

# 如果使用 MySQL 8.0+，取消注释以下两行并注释上面两行：
# SPRING_DATASOURCE_URL=jdbc:mysql://localhost:3306/poetize?useUnicode=true&characterEncoding=utf-8&serverTimezone=Asia/Shanghai
# SPRING_DATASOURCE_DRIVER_CLASS_NAME=com.mysql.cj.jdbc.Driver

# 数据库连接池配置
SPRING_DATASOURCE_DRUID_INITIAL_SIZE=5
SPRING_DATASOURCE_DRUID_MIN_IDLE=5
SPRING_DATASOURCE_DRUID_MAX_ACTIVE=50

# ========== Redis 配置 ==========
# 如果 Redis 未设置密码，保持为空即可
# 如果 Redis 设置了密码，请填写实际密码
SPRING_REDIS_HOST=localhost
SPRING_REDIS_PORT=6379
SPRING_REDIS_PASSWORD=
SPRING_REDIS_DATABASE=0

# ========== JVM 参数 ==========
# 注意：Java 25 项目使用了预览特性，启动时必须加 --enable-preview（已在 systemd 服务中配置）
# 根据服务器内存配置（注意留给系统和其他服务一些资源）：
# - 2GB 内存：-Xms256m -Xmx512m
# - 4GB 内存：-Xms512m -Xmx1024m
# - 8GB 内存：-Xms1024m -Xmx2048m
# - 16GB+ 内存：-Xms2048m -Xmx4096m
JVM_OPTS=-Xms512m -Xmx1024m -XX:+UseZGC

# ========== 文件路径配置 ==========
# 用户上传文件存储路径（Java 后端提供 /static/** 资源映射）
LOCAL_UPLOADURL=/www/wwwroot/poetize/static/

# 预渲染配置（SEO 预渲染页面）
PRERENDER_TEMPLATE_PATH=/www/wwwroot/poetize/index.html
PRERENDER_OUTPUT_ROOT=/www/wwwroot/poetize/prerender
PRERENDER_ADMIN_TEMPLATE_PATH=/www/wwwroot/poetize/admin/index.html
PRERENDER_ADMIN_OUTPUT_ROOT=/www/wwwroot/poetize/admin/prerender
EOF
```

**按需修改**：
1. `SPRING_DATASOURCE_PASSWORD` - 替换为步骤 3.3 创建的数据库密码
2. 如果使用 MySQL 而非 MariaDB，取消注释 MySQL 的两行，注释掉 MariaDB 的两行
3. 如果 Redis 有密码，修改 `SPRING_REDIS_PASSWORD=your_redis_password`
4. 根据服务器内存调整 `JVM_OPTS` 中的 `-Xms` 和 `-Xmx` 参数
5. 如果上传文件存储路径不同，修改 `LOCAL_UPLOADURL`

#### 3.7.1 同步数据库中的本地存储路径

项目启动时会从 `sys_config` 表加载配置，并且数据库配置优先级高于 `.env`。初始化 SQL 中的 `local.uploadUrl` 默认是 Docker 容器路径 `/app/static/`，宝塔裸机部署必须改成实际目录 `/www/wwwroot/poetize/static/`。

在宝塔终端执行：

```bash
mysql -u root -p poetize << 'SQL'
UPDATE sys_config
SET config_value = '/www/wwwroot/poetize/static/'
WHERE config_key = 'local.uploadUrl';

UPDATE sys_config
SET config_value = '/static/'
WHERE config_key = 'local.downloadUrl';
SQL
```

如果你在宝塔后台修改过本地存储目录，也要保持这三个位置一致：

- `.env` 中的 `LOCAL_UPLOADURL`
- 数据库 `sys_config.local.uploadUrl`
- Nginx 中 `/static`、`/static/articleFile` 指向的本机目录

### 3.8 创建 Java 后端服务（systemd 方式）

为了方便管理，创建一个 systemd 服务文件来管理 Java 应用，并加载 `.env` 中的环境变量。

创建 systemd 服务文件：

```bash
cat << 'EOF' | sudo tee /etc/systemd/system/poetize-server.service
[Unit]
Description=POETIZE Server
After=network.target mariadb.service

[Service]
Type=simple
User=root
WorkingDirectory=/home/poetize/poetize-server/poetry-web/target

# 加载环境变量文件
EnvironmentFile=/home/poetize/.env

ExecStart=/usr/local/jdk-25+9/bin/java --enable-preview ${JVM_OPTS} -jar poetize-server-exec.jar
Restart=on-failure
RestartSec=10

# 日志输出到 journalctl
StandardOutput=journal
StandardError=journal
SyslogIdentifier=poetize-server

[Install]
WantedBy=multi-user.target
EOF

# 重新加载 systemd
sudo systemctl daemon-reload

# 启用并启动服务
sudo systemctl enable poetize-server
sudo systemctl start poetize-server

# 检查服务状态
sudo systemctl status poetize-server
```

> **说明**：
> - `ExecStart` 中使用了 JDK 25 的完整路径 `/usr/local/jdk-25+9/bin/java`，确保 systemd 能找到正确的 Java 版本
> - `--enable-preview` 是必须的，本项目使用了 Java 预览特性
> - 日志通过 `journalctl` 查看，不需要额外的日志文件

**修改配置后**：编辑 `/home/poetize/.env` 文件，然后执行以下命令重启服务：

```bash
sudo systemctl restart poetize-server
```

#### 替代方案：使用宝塔「网站 > Java项目」管理

如果你更喜欢通过宝塔 GUI 管理 Java 项目，也可以使用宝塔的 **网站 > Java项目** 功能替代 systemd 方式。步骤如下：

1. 在宝塔左侧菜单选择 **网站** → **Java项目**
2. 点击 **添加Java项目**
3. 填写配置：
   - **项目名称**：`poetize-server`
   - **项目路径**：`/home/poetize/poetize-server/poetry-web/target`
   - **项目JAR**：`poetize-server-exec.jar`
   - **项目JDK**：选择手动安装的 JDK 25（路径 `/usr/local/jdk-25+9`）
   - **项目端口**：`8081`
   - **JVM参数**：`--enable-preview -Xms512m -Xmx1024m -XX:+UseZGC`（**必须包含 `--enable-preview`**）
4. 在 **环境变量** 中添加 `.env` 文件中的所有变量（数据库、Redis、文件路径等）
5. 点击 **提交**

> **注意**：
> - 宝塔 Java 项目管理器本质上也是通过 systemd 管理进程，只是提供了 GUI 界面
> - **必须**在 JVM 参数中添加 `--enable-preview`，否则 Java 应用无法启动
> - 如果宝塔无法识别手动安装的 JDK 25，请继续使用上面的 systemd 方式

### 3.9 配置 Nginx 反向代理

在宝塔面板左侧菜单选择 **网站** → **PHP项目**：

1. 点击 **添加站点**
2. 在弹出的窗口中填写：
   - **域名**：填写你的域名（如 `your-domain.com`），多个域名换行填写
   - **备注**：可选，如 `POETIZE博客`
   - **根目录**：默认为 `/www/wwwroot/你的域名`，**修改为** `/www/wwwroot/poetize`
   - **FTP**：选择 **不创建**
   - **数据库**：选择 **不创建**（已在步骤 3.3 中单独创建）
   - **PHP版本**：选择 **纯静态**
3. 点击 **提交**

> **注意**：根目录必须修改为 `/www/wwwroot/poetize`，与前端构建产物的部署路径一致。

#### 3.9.1 编辑 Nginx 配置

在宝塔 **网站** 列表中选择刚创建的网站，点击 **设置** → **配置文件**，将 `server { }` 内的内容替换为下方配置。

> **必须保留 `#CERT-APPLY-CHECK` 标记**，宝塔通过该标记定位 SSL 证书验证文件，删除后证书自动续期会失效。下方配置已包含该标记，`include` 路径中的域名保留宝塔已生成的值即可。`server_name` 只保留主域名，`www` 等子域名应通过 301 重定向指向主域名（见[7.2 配置多域名](#72-配置多域名)），避免 SEO 重复内容问题。

```nginx
server {
    listen 80;
    server_name your-domain.com;
    
    #CERT-APPLY-CHECK--START
    # 用于SSL证书申请时的文件验证相关配置 -- 请勿删除
    include /www/server/panel/vhost/nginx/well-known/your-domain.com.conf;
    #CERT-APPLY-CHECK--END
    include /www/server/panel/vhost/nginx/extension/your-domain.com/*.conf;
    
    # 强制 HTTPS（申请 SSL 证书后在宝塔 SSL 设置中开启强制 HTTPS，不要手动取消注释）
    # return 301 https://$server_name$request_uri;
    
    # 默认字符集
    charset utf-8;
    
    # 安全头
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-XSS-Protection "1; mode=block" always;
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;
    
    # Gzip 压缩
    gzip on;
    gzip_vary on;
    gzip_proxied any;
    gzip_comp_level 6;
    gzip_min_length 256;
    gzip_types text/plain text/css application/json application/javascript text/xml application/xml application/xml+rss text/javascript;
    
    # 限制请求大小
    client_max_body_size 120M;
    
    # ===== 后台管理前端 =====
    
    # 后台管理静态资源
    location ^~ /admin/assets/ {
        alias /www/wwwroot/poetize/admin/assets/;
        expires 30d;
        add_header Cache-Control "public, no-transform";
    }
    
    location ^~ /admin/static/ {
        alias /www/wwwroot/poetize/admin/static/;
        expires 30d;
        add_header Cache-Control "public, no-transform";
    }
    
    # 后台管理 SPA 路由
    location ^~ /admin {
        alias /www/wwwroot/poetize/admin;
        index index.html;
        try_files $uri $uri/ /prerender/index.html @admin_fallback;
        
        # index.html 不缓存
        location = /admin/index.html {
            root /www/wwwroot/poetize;
            try_files /admin/prerender/index.html /admin/index.html =404;
            expires -1;
            add_header Cache-Control "no-store, no-cache, must-revalidate";
        }
    }
    
    location @admin_fallback {
        root /www/wwwroot/poetize;
        try_files /admin/prerender/index.html /admin/index.html =404;
    }
    
    # ===== API 路由配置 =====
    
    # 后端 API 代理（/api/ 前缀，去掉前缀后转发）
    location ^~ /api/ {
        proxy_pass http://127.0.0.1:8081/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_http_version 1.1;
        proxy_connect_timeout 60s;
        proxy_send_timeout 60s;
        proxy_read_timeout 60s;
    }
    
    # 用户相关 API
    location ~ ^/user/(login|register|logout|updateUserInfo|getCode|getCodeForBind|updateUserSecretInfo|bindingUserSecretInfo|getUserInfo|listUser|saveUser|updatePassword|updateAdminInfo|deleteUsers|getAdminUserInfo|updateAdminConfig) {
        proxy_pass http://127.0.0.1:8081;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_http_version 1.1;
    }
    
    # OAuth 第三方登录
    location ^~ /login/ {
        rewrite ^/login/(.*)$ /oauth/login/$1 break;
        proxy_pass http://127.0.0.1:8081;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_redirect off;
    }
    
    location ^~ /callback/ {
        rewrite ^/callback/(.*)$ /oauth/callback/$1 break;
        proxy_pass http://127.0.0.1:8081;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_redirect off;
    }
    
    # SEO 相关路由
    location = /robots.txt {
        proxy_pass http://127.0.0.1:8081/seo/robots.txt;
        proxy_set_header Host $host;
        add_header Cache-Control "public, max-age=3600";
    }
    
    location = /manifest.json {
        proxy_pass http://127.0.0.1:8081/seo/manifest.json;
        proxy_set_header Host $host;
        add_header Cache-Control "no-cache";
    }
    
    location = /favicon.ico {
        proxy_pass http://127.0.0.1:8081/seo/favicon.ico;
        proxy_set_header Host $host;
        add_header Cache-Control "public, max-age=3600";
    }

    location = /sitemap.xml {
        proxy_pass http://127.0.0.1:8081/sitemap.xml;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Accept "application/xml";
        add_header Cache-Control "public, max-age=3600";
    }

    # IndexNow / 搜索引擎站点验证文件
    location ~ "^/([a-zA-Z0-9\-]{8,128})\.txt$" {
        proxy_pass http://127.0.0.1:8081/$1.txt;
        proxy_set_header Host $host;
        add_header Cache-Control "public, max-age=3600";
    }
    
    # PWA Service Worker
    location = /sw.js {
        root /www/wwwroot/poetize;
        expires -1;
        add_header Cache-Control "no-store, no-cache, must-revalidate";
        add_header Content-Type "application/javascript; charset=utf-8";
    }
    
    # 聊天室 WebSocket 端点
    location /ws/im {
        proxy_pass http://127.0.0.1:8081;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 600s;
    }

    # 聊天室页面（前端路由）
    location ^~ /im {
        root /www/wwwroot/poetize;
        index index.html;
        try_files $uri $uri/ /index.html;
    }
    
    # 聊天室静态资源
    location ^~ /im/static/ {
        alias /www/wwwroot/poetize/static/;
        try_files $uri =404;
        expires 30d;
        add_header Cache-Control "public, no-transform";
    }

    # 兼容 /assets/** 访问，实际文件位于 /static/assets/**
    location ^~ /assets/ {
        alias /www/wwwroot/poetize/static/assets/;
        try_files $uri =404;
        expires 30d;
        add_header Cache-Control "public, no-transform";
    }
    
    # 编辑器附件兜底：可执行/脚本类文件即使被直接访问，也强制下载
    location ~* ^/static/articleFile/(.*\.(exe|dll|bat|cmd|com|msi|jar|class|scr|vbs|vbe|js|jse|wsf|wsh|ps1|sh|bash|zsh|py|pyc|pyw|pl|perl|rb|go|rs|rust|c|cpp|cc|cxx|php|php3|php4|php5|phtml|phar|jsp|jspx|jsf|jspa|jhtml|asp|aspx|asa|asax|ascx|ashx|asmx|docm|xlsm|pptm))$ {
        alias /www/wwwroot/poetize/static/articleFile/$1;
        expires 30d;
        add_header Cache-Control "public, no-transform";
        add_header Content-Disposition "attachment";
        add_header X-Content-Type-Options "nosniff";
    }

    # Live2D 模型和资源
    location ^~ /static/live2d_api/ {
        root /www/wwwroot/poetize;
        try_files $uri =404;
        expires 30d;
        add_header Cache-Control "public, max-age=2592000";
        add_header Access-Control-Allow-Origin *;
        add_header Access-Control-Allow-Methods "GET, OPTIONS";
    }

    location ^~ /static/live2d-widget/ {
        root /www/wwwroot/poetize;
        try_files $uri =404;
        expires 7d;
        add_header Cache-Control "public, max-age=604800";
    }

    # 上传静态资源
    location /static {
        alias /www/wwwroot/poetize/static;
        try_files $uri =404;
        expires 30d;
        add_header Cache-Control "public, no-transform";
    }

    # ===== 安全防护 =====
    
    # 防止目录遍历攻击
    location ~* \.\./  {
        return 403;

    # 禁止访问隐藏文件（排除 .well-known 以支持 SSL 证书验证）
    location ~ /\.(?!well-known/) {
        return 403;

    location ~* \.(htaccess|htpasswd|env|config|ini|log|sql|bak|backup|old|tmp|swp|swo)$ {

    # 常用页面静态预渲染

    location = /music {

    }

    location = /letter {

        try_files /prerender/letter/index.html @spa_fallback;

    location ~ ^/sort/([0-9]+)$ {

        root /www/wwwroot/poetize;
        try_files $uri $uri/ /index.html;
    }

    # ===== 主站前端 =====
    
    # 主站 SPA 路由

        root /www/wwwroot/poetize;
        try_files $uri $uri/ /index.html;
        index index.html index.htm;
    }
    
    # 主站 index.html 不缓存
    location = /index.html {
        root /www/wwwroot/poetize;
```

#### 3.9.2 宝塔 Nginx 与 Docker Nginx 的 SEO 差异

Docker 部署的 SEO 链路已经迁移到后端预渲染和 Nginx 原生 `try_files`，不再依赖 OpenResty Lua 脚本。宝塔默认安装的普通 Nginx 也可以使用同样的思路：优先读取后端生成的 `prerender/` 静态 HTML，找不到时再回退到前端 SPA。

上面的宝塔配置已经用纯 Nginx `try_files` 支持主要预渲染页面，包括首页、文章页、分类页和常用静态页面。需要注意的是，SEO 效果现在以 Java 后端生成的预渲染文件为准：

- 修改网站信息、SEO 配置或文章后，后端会重新触发预渲染。
- Nginx 只负责按路径选择已有的预渲染 HTML，不再动态改写 HTML 内容。
- 如果某个页面还没生成预渲染文件，会回退到前端 SPA。

部署后可以用“查看页面源代码”确认文章正文和 SEO 标签已经出现在 HTML 中。

#### 数据库迁移

项目更新后如果数据库结构有变化，需要手动执行增量迁移脚本：

1. 在宝塔左侧选择 **数据库** → 选择 `poetize` → 点击 **SQL 编辑器**
2. 先查询已执行过的迁移版本，避免重复执行：
   ```sql
   SELECT version, executed_at FROM db_migrations ORDER BY version;
   ```
3. 在宝塔 **文件** 中查看 `/home/poetize/poetize-server/sql/` 目录，找到未执行过的迁移脚本（文件名格式为 `YYYYMMDDHHMM.sql`）
4. 打开未执行的迁移脚本，复制其中的 SQL 语句到 **SQL 编辑器** 中执行（按文件名时间戳顺序逐个执行）
5. 也可以在宝塔 **数据库** 中选择 `poetize` → 点击 **导入**，直接导入 `.sql` 文件

> **注意**：
> - 迁移脚本必须按文件名中的时间戳顺序逐个执行，不能跳过
> - 已执行过的脚本会记录在 `db_migrations` 表中，执行前请先查询避免重复执行
> - 执行迁移前建议先在宝塔 **数据库** 中点击 **备份** 备份数据库

```bash
nano /home/poetize/.env

# 根据服务器内存修改 JVM_OPTS（注意：EnvironmentFile 中不要加引号）：
# 2GB 内存：JVM_OPTS=-Xms256m -Xmx512m -XX:+UseZGC
# 4GB 内存：JVM_OPTS=-Xms512m -Xmx1024m -XX:+UseZGC
# 8GB 内存：JVM_OPTS=-Xms1024m -Xmx2048m -XX:+UseZGC
# 16GB+ 内存：JVM_OPTS=-Xms2048m -Xmx4096m -XX:+UseZGC
```

保存后重启服务：

```bash
sudo systemctl restart poetize-server
```

### 7.2 配置多域名

> **不要**将多个域名直接写在同一个 `server_name` 中，否则同一内容会被多个 URL 访问，搜索引擎视为重复内容，分散页面权重。

正确做法是为每个非主域名创建独立的 `server` 块，用 301 重定向到主域名。在 Nginx 配置文件中，主站 `server { }` 块**之前**添加：

```nginx
# 将 www 和其他域名 301 重定向到主域名
server {
    listen 80;
    server_name www.your-domain.com another-domain.com;
    return 301 https://your-domain.com$request_uri;
}
```

这样所有非主域名的访问都会被永久重定向到主域名，SEO 权重集中到一个域名上。

然后重载 Nginx：

```bash
sudo systemctl reload nginx
```

### 7.3 启用 Gzip 压缩

上方 Nginx 配置中已包含 Gzip 压缩配置。如需进一步调整，可修改 Nginx 配置中的 gzip 相关参数：

```nginx
gzip on;
gzip_vary on;
gzip_proxied any;
gzip_comp_level 6;
gzip_min_length 256;
gzip_types text/plain text/css text/xml text/javascript 
           application/x-javascript application/xml+rss 
           application/json application/javascript;
```

## 9. 常见问题

### Q: 部署失败，Java 应用无法启动？

**检查步骤**：

1. 查看 Java 应用日志：
   ```bash
   journalctl -u poetize-server -f
   ```

2. 检查数据库连接是否正常：
   ```bash
   mysql -u poetize -p -e "SELECT 1;"
   ```

3. 检查 Java 版本是否正确：
   ```bash
   java -version  # 应该是 JDK 25
   ```

4. 检查端口是否被占用：
   ```bash
   sudo lsof -i :8081
   ```

5. 重启应用：
   ```bash
   sudo systemctl restart poetize-server
   ```

### Q: 网站无法访问，Nginx 502 错误？

**解决方案**：

1. 检查后端是否运行：
   ```bash
   sudo systemctl status poetize-server
   ```

2. 检查 Nginx 配置是否正确：
   ```bash
   sudo nginx -t
   ```

3. 查看 Nginx 错误日志：
   ```bash
   tail -f /var/log/nginx/error.log
   ```

4. 检查防火墙是否开放端口：
   ```bash
   sudo ufw allow 80
   sudo ufw allow 443
   sudo ufw allow 8081
   ```

### Q: 前端编译失败或编译很慢？

**解决方案**：

1. 清理 npm 缓存：
   ```bash
   npm cache clean --force
   ```

2. 删除 node_modules 重新安装：
   ```bash
   cd /home/poetize/poetize-web
   rm -rf node_modules package-lock.json
   npm install
   ```

3. 使用淘宝 npm 镜像加速：
   ```bash
   npm config set registry https://registry.npmmirror.com
   ```

### Q: 数据库连接失败？

**排查步骤**：

1. 检查 MariaDB 是否运行：
   ```bash
   sudo systemctl status mariadb
   ```

2. 尝试直接登录数据库：
   ```bash
   mysql -u poetize -p
   ```

3. 检查用户权限：
   ```bash
   mysql -u root -p
   SELECT User, Host FROM mysql.user WHERE User='poetize';
   ```

4. 重置密码：
   ```bash
   mysql -u root -p
   ALTER USER 'poetize'@'localhost' IDENTIFIED BY 'new_password';
   FLUSH PRIVILEGES;
   ```

### Q: 磁盘满了怎么办？

**清理步骤**：

1. 查看磁盘使用：
   ```bash
   df -h
   du -sh /home/poetize
   du -sh /var/log
   du -sh /www/wwwroot
   ```

2. 清理日志文件：
   ```bash
   # 清理超过30天的日志
   find /var/log -type f -mtime +30 -delete
   ```

3. 清理 npm 缓存：
   ```bash
   npm cache clean --force
   ```

4. 压缩旧数据库备份：
   ```bash
   gzip /home/poetize/poetize-backup-*.sql
   ```

### Q: Redis 无法连接？

**解决方案**：

1. 检查 Redis 服务：
   ```bash
   sudo systemctl status redis-server
   ```

2. 进入 Redis 命令行测试：
   ```bash
   redis-cli
   PING  # 应该返回 PONG
   ```

3. 重启 Redis：
   ```bash
   sudo systemctl restart redis-server
   ```

4. 检查 Redis 是否需要密码：
   ```bash
   redis-cli -a your_password PING
   ```

### Q: WebSocket 聊天室无法连接？

**排查步骤**：

1. 检查后端是否在运行：
   ```bash
   curl http://127.0.0.1:8081/actuator/health
   ```

2. 检查 Nginx 配置中 WebSocket 代理是否正确配置
3. 查看浏览器控制台错误信息
4. 检查防火墙是否开放 443 端口（WebSocket 走 HTTPS）

### Q: HTTPS 证书过期？

**续期步骤**：

1. 在宝塔 **网站** 中选择网站，点击 **设置** → **SSL**
2. 点击 **续期** 按钮
3. Let's Encrypt 证书有效期为 90 天，宝塔默认会自动续期，无需手动操作

### Q: 如何迁移到其他服务器？

**迁移步骤**：

1. 在旧服务器备份数据：
   ```bash
   # 备份数据库
   mysqldump -u poetize -p poetize > /tmp/poetize-backup.sql
   
   # 备份项目文件
   tar -czf /tmp/poetize-src.tar.gz /home/poetize
   
   # 备份静态文件
   tar -czf /tmp/poetize-web.tar.gz /www/wwwroot/poetize
   ```

2. 将文件传输到新服务器（使用 scp 或宝塔面板）

3. 在新服务器重复本教程的部署步骤
4. 恢复数据库和文件
5. 修改 DNS 指向新服务器 IP

### Q: 如何查看项目版本？

```bash
# 查看 Git 版本
cd /home/poetize
git log --oneline | head -1

# 查看 pom.xml 版本
grep -oP '<version>\K[^<]+' /home/poetize/poetize-server/poetry-web/pom.xml | head -1
```

## 10. 性能优化建议

### 10.1 启用 Redis 缓存

1. 确保 Redis 正在运行
2. 在后台管理 → 配置管理中启用 Redis
3. 验证缓存是否工作：
   ```bash
   redis-cli
   KEYS *
   ```

### 10.2 启用 Gzip 压缩

在 Nginx 配置中添加（通常已默认启用）：

```nginx
gzip on;
gzip_min_length 1000;
gzip_types text/plain text/css text/xml application/json;
```

### 10.3 优化 Java 应用性能

编辑 `/home/poetize/.env` 调整 JVM 参数。根据服务器内存配置：

```bash
# 查看服务器内存
free -h

# 编辑 .env 文件
nano /home/poetize/.env

# 调整 JVM_OPTS（建议保留 30% 内存给系统和其他服务，EnvironmentFile 中不要加引号）：
# 例如 2GB 服务器：-Xms256m -Xmx512m
# 例如 4GB 服务器：-Xms512m -Xmx1024m
# 例如 8GB 服务器：-Xms1024m -Xmx2048m
JVM_OPTS=-Xms512m -Xmx1024m -XX:+UseZGC
```

保存后重启服务：

```bash
sudo systemctl restart poetize-server
```

### 10.4 启用 CDN

配置静态资源 CDN（如七牛云、阿里云 CDN）：

1. 在后台管理 → 配置管理 → CDN 配置中填写 CDN 域名
2. 需要修改前端 `vite.config.js` 的 `base` 配置

### 10.5 调整数据库连接池

项目使用 Druid 连接池，通过环境变量配置。编辑 `/home/poetize/.env`：

```bash
# 初始连接数
SPRING_DATASOURCE_DRUID_INITIAL_SIZE=5
# 最小空闲连接数
SPRING_DATASOURCE_DRUID_MIN_IDLE=5
# 最大活跃连接数
SPRING_DATASOURCE_DRUID_MAX_ACTIVE=64
```
